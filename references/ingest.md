# 采集入口：微信里的东西怎么一条条搬进来

微信不开放数据接口。所有内容进入 WorkBuddy 都只有一条路：**用户在微信客户端里主动"分享"**。
本文件按内容来源，给出每条路径的实际操作、能拿到什么、拿不到什么。

---

## 0. 先分清四种来源

| 来源 | 微信里的位置 | 能否批量 | 落到 WorkBuddy 的形态 |
|---|---|---|---|
| 聊天记录 | 任意会话 | 可（合并转发） | 聊天记录包 `.zip` → `聊天记录.txt` |
| 收藏 | 我 → 收藏 | 可（合并转发 / 逐条分享） | 同上，或文件 / 链接 |
| 朋友圈 | 发现 → 朋友圈 | 不可（只能自己逐条） | 截图 / 复制文字 |
| 公众号文章 | 订阅号 / 聊天里的链接 | 可（逐篇分享链接） | 链接 → 抓正文 |

---

## 1. 聊天记录（最主要来源）

### 单条 / 少量消息
1. 在微信里长按消息 →「转发」→ 选择目标（WorkBuddy 入口 / 文件传输助手）
2. 到 WorkBuddy 侧完成分享
3. 上下文中出现 `@wechat-chat-history:"聊天记录_YYYYMMDD_HHMMSS.zip"`

### 一段对话（推荐做法）
1. 进入会话 → 长按任意消息 →「多选」
2. **按你需要的顺序**逐条勾选（微信按勾选顺序记录，不是按时间重排）
3. 点「合并转发」→ 选「逐条转发」或「合并转发」
4. **关键**：合并转发生成的是一个"聊天记录"卡片，它保留了发送人和时间——这是重建时间线的唯一可靠依据
5. 分享到 WorkBuddy

> 为什么要"合并"：如果逐条单独转发，每条都是一个独立分享单元，时间戳会被分享时刻覆盖，原始时间丢失。

### 一整个群的历史
无法一次导出。按「周」或「话题」切段，每次合并转发一段，并在 `--batch-id` 里标明段号：
```
demo群_202610W1, demo群_202610W2, ...
```
段与段之间的顺序由用户告知，不要自行推测。

---

## 2. 收藏

收藏是混合形态，先分类再处理：

| 收藏类型 | 处理方式 |
|---|---|
| 文字笔记 | 逐条转发（或合并转发多条） |
| 图片 | 转发 → 图片文件 → 走图片路径 |
| 链接（公众号/网页） | 转发链接 → 走链接路径 |
| 文件（PDF/Word） | 转发文件 → 走文件路径 |
| 聊天记录（收藏的对话） | 转发 → 聊天记录包 |
| 语音 | 播放后长按「转文字」，复制文字转发 |

批量整理收藏时，建议一次只处理一种类型，用 `--source favorite` 标记，避免类型混杂难以归类。

---

## 3. 朋友圈

**边界**：只能处理用户自己在自己手机上看到并主动导出的内容；他人朋友圈无法抓取，也没有"导出全部朋友圈"的官方能力。

三种可行做法（按保真度排序）：

1. **单条截图** → 图片 → OCR + 场景描述 → 落 `M03 生活日记`
2. **复制文字** → 文本 → 保留原文与发布时间（时间需用户口述或用截图时间）
3. **批量截图后合并转发** → 一个图片包 → 逐张 OCR，按截图顺序还原时间线

朋友圈数据的关键字段是 **发布时间** 和 **当时的心情**，发布人默认是用户本人（`is_self: 是`）。

---

## 4. 公众号文章

1. 在微信里打开文章 →「…」→ 复制链接 / 分享
2. 分享到 WorkBuddy → 上下文出现链接
3. 用 `WebFetch` 抓正文，抽：标题、作者、发布时间、正文、关键论点

抓取失败（防爬、需登录、付费墙）时按降级链处理：

```
正文抓取成功 → 全文入库
    ↓ 失败
标题 + 链接 + 首段（从分享卡片描述里取）
    ↓ 仍失败
标题 + 链接 + 用户口述的一句话摘要（标注 confidence: low）
```

公众号文章入库时，`source_type: official`，作者记为发送人，用户在文中的批注单独记一条，不要混进正文。

---

## 5. 文件与媒体

图片、语音、视频、PDF、Office 文件的处理路径见 `media-handling.md`。
原则：**原文件不必入库，文字与描述必须入库**。资料库存不下大量二进制，也没必要。

---

## 6. 采集时的四个必问

每次接收分享后，确认这四件事再动手：

1. **这是谁说的？**（发送人，保持原昵称不改写）
2. **什么时候？**（原始时间；时间缺失就问，别用分享时刻代替）
3. **这是几段？**（一个包还是多个包，顺序如何）
4. **要什么？**（存档 / 某种模式，决定抽什么）

只问必要的，能推断的不要问。用户只丢一个包没说别的，按 `M01 冷存档` 处理。
