# 数据结构：从一条微信消息到可分析的记录

微信给的是"人话"，分析要的是"字段"。中间这层转换决定了知识库能不能用。

---

## 三层结构（不要跳过任何一层）

```
第 1 层  原始层 raw/
         └ 原封不动的聊天记录包 + 聊天记录.txt + 原文 Markdown
         作用：永不可再生。任何时候都要能回答"原话是什么"

第 2 层  规范层 records.jsonl / records.csv / 资料库数据表
         └ 一行一条消息，28 个字段
         作用：可筛选、可统计、可去重、可增量合并

第 3 层  派生层 topics/ people/ timeline/ INDEX.md
         └ 按主题、人物、时间重新聚合
         作用：给人看，回答"我要找的那件事在哪"
```

**铁律：第 3 层可以重算，第 1 层不能重建。** 所以原文永远保留，摘要只是叠加。

---

## 规范层字段表（28 字段）

由 `scripts/build_records.py` 自动生成，字段含义如下。

### 标识与来源

| 字段 | 类型 | 说明 | 示例 |
|---|---|---|---|
| `record_id` | str | 批次内序号，唯一 | `wch-20261029_1252-0001` |
| `batch_id` | str | 一次分享 = 一个批次 | `20261029_1344` |
| `source_type` | enum | `chat` / `favorite` / `moments` / `official` / `mixed` | `chat` |
| `chat_name` | str | 会话名或群名，未知留空 | `项目讨论群` |
| `sender` | str | 说话人原昵称，**不改写** | `·阿禾` |
| `is_self` | enum | `是` / `否` / 空=未知 | 空 |

### 时间（分析的骨架）

| 字段 | 类型 | 说明 |
|---|---|---|
| `msg_time` | ISO | `2026-10-29 12:52:00`，原始发送时间，非分享时间 |
| `msg_date` | date | `2026-10-29`，用于按天分组 |
| `msg_hour` | int | 0–23，用于时段分布 |
| `weekday` | str | 周一…周日 |

### 内容

| 字段 | 类型 | 说明 |
|---|---|---|
| `msg_type` | enum | `text` `image` `voice` `video` `file` `link` `sticker` `miniapp` `official` `mixed` |
| `content_raw` | text | 原文，含表情占位符 `[图片]` `[表情]` |
| `content_clean` | text | 压缩多余空格后的版本，用于检索 |
| `char_len` | int | 字符数 |
| `emoji_tags` | str | 抽出的 `[送心]` 类标签，`\|` 分隔 |

### 媒介

| 字段 | 类型 | 说明 |
|---|---|---|
| `media_path` | path | 本地文件路径（若已落盘） |
| `media_desc` | text | **一句话描述**，图片/语音必填，不能空 |

### 语义（可空的推断字段）

| 字段 | 类型 | 说明 |
|---|---|---|
| `thread_id` | str | 同一条对话线索；默认按日期 |
| `topic_tags` | str | 主题分类，取自固定 13 类或自定 |
| `emotion` | str | 情绪标签，取自固定 12 类 |
| `sentiment_score` | float | -1…1，可选 |
| `entities_people` | str | 涉及的人 |
| `entities_place` | str | 涉及的地点 |
| `action_item` | str | 抽出的待办，一句话 |
| `importance` | int | 1–5，0=未评 |

### 治理

| 字段 | 类型 | 说明 |
|---|---|---|
| `mode` | str | 场景模式 M01–M12 |
| `privacy_level` | enum | `normal` / `sensitive` / `restricted` |
| `confidence` | enum | `high` / `low`（OCR 错、语音转写可疑时标 low） |
| `hash_dup` | str | 去重指纹（批次+人+时间+内容） |
| `kb_url` | url | 归档文档链接 |
| `ingested_at` | ts | 入库时刻 |

### 填字段的三条纪律

1. **空比错好**：推不出就留空，让后续人工或二次分析补。不要用"推测值"污染字段。
2. **原文永不动**：`content_raw` 一旦写入不再修改；清洗只发生在 `content_clean`。
3. **姓名不改写**：`·阿禾` 就是 `·阿禾`，即使看起来像多余符号。需要统一称谓就在 `entities_people` 里别名。

## 资料库落地形态：选哪种？

| 形态 | 适合 | 不适合 |
|---|---|---|
| **数据表（database）** | 需要筛选、排序、按情绪/主题/时间查 | 只是想读原文 |
| **文档（doc）** | 一次分享的完整存档，给人读 | 上百条要横向比较 |
| **CSV 文件** | 导出到 Excel 做透视、做作业 | 长期作为唯一副本 |
| **看板（HTML 页）** | 展示给别人看、做汇报 | 精细编辑 |

推荐组合：**数据表存规范层 + 文档存可读副本 + CSV 做分析出口**。
数据表的建表与写入见 `library-cli.md` §4，字段映射见 `scripts/build_db_payload.py`。

## 目录约定（资料库内）

```
微信记忆库/
├── 00_收件箱/            新分享进来、还没处理的
├── 01_原始包/            每个批次的原文 Markdown（第 1 层）
├── 02_记录表/            数据表 + records.csv 导出
├── 03_思维资源/          按模式产出（M02/M05 等）
├── 04_人物档案/          M04/M06 产出，一人一页
├── 05_时间轴/            M03 产出，按月一页
├── 06_索引/
│   └── INDEX.md          总目录 + 统计 + 最近条目
└── _模式配置.md          当前启用的模式与规则
```

> 目录不是目的。小于 50 条时用 00/01 两个目录就够，别为了"整齐"先造一堆空文件夹。

```markdown

- 更新时间：2026-10-29 14:20
- 批次总数：4
- 消息总数：13
- 时间跨度：2026-10-28 至 2026-10-29
- 当前模式：M01 冷存档

## 批次清单

| 批次 | 来源 | 条数 | 时间范围 | 文档 |
|---|---|---|---|---|
| 20261029_1344 | 聊天 | 1 | 10-29 13:44 | [链接](...) |

## 最近 5 条

1. 2026-10-29 13:44 ·风筝：使用Three.js创建一个完整、可交互的DJI action4 3D拆解可视化页面…

## 待处理
```
