# 边界：能做什么，不能做什么，以及为什么

这一章不是免责声明，是**操作前提**。搞不清边界，后面每一步都会返工。

---

## 一、根本限制：没有"批量导入"这个动作

WorkBuddy 拿不到微信的数据库、聊天文件、通讯录。**唯一的输入通道是用户在微信客户端里主动"分享"**。

所以：

| 用户想要 | 现实 | 正确回应 |
|---|---|---|
| "把我全部微信记录导进来" | 做不到 | 说明只能一批批分享，给出分批方案 |
| "扫一下我手机里的聊天" | 做不到 | 同上 |
| "把我转发的 500 条一次搞定" | 做不到 | 教他合并转发的正确姿势 |
| "把这个包整理一下" | 可以 | 直接做 |

**"单一元素"原则**：一次分享 = 一个分享单元 = 一次处理。一个包就是一批，不要指望它自动包含别的东西。

---

## 二、批量：唯一的合法路径

要处理多条内容，必须走这条路，顺序不能变：

```
① 用户在微信里多选消息（按需要的顺序）
        ↓
② 「合并转发」→ 生成一条"聊天记录"卡片
        ↓
③ 这张卡片分享到 WorkBuddy
        ↓
④ 落成一个 .zip（内含 聊天记录.txt）
        ↓
⑤ 解析 → 结构化 → 归档
```

### 三条硬规则

**规则 1：顺序由用户决定，不由系统推断**
微信的"多选"按**勾选顺序**记录，不按时间重排。合并转发保留这个顺序。
- 用户按时间顺序勾 → 得到时间线
- 用户乱序勾 → 得到乱序，且**无法自动修正**

所以必须在开工前问一句："这些消息是按时间顺序选的吗？"
若用户不确定 → 全部标记 `order_confidence: low`，并且**不要基于顺序做任何时间推断**。

**规则 2：必须"合并"，不能逐条**
逐条转发 = N 个独立分享单元，每条的时间戳变成"分享那一刻"，原始时间永久丢失。
合并转发 = 1 个单元，发送人和原始时间都保留。

**规则 3：一包一段，段间顺序由用户告知**
单个包建议 ≤ 500 条消息、≤ 20MB。超了会：
- 解析慢、上下文塞不下
- 中间出错难以定位

切段方案（按需选一种）：
- 按时间：`2026-10 上旬 / 中旬 / 下旬`
- 按话题：`项目启动期 / 执行期 / 复盘期`
- 按人：`与A的对话 / 与B的对话`

每段用不同 `--batch-id`，并在 `INDEX.md` 记录段间顺序。**不要自己猜顺序。**

## 三、来源边界

| 来源 | 能做 | 不能做 |
|---|---|---|
| 自己的聊天 | 全部可做 | — |
| 群聊 | 可做，注意第三方隐私 | 不能"导出全群历史" |
| 他人朋友圈 | 只能处理用户自己截图/复制的部分 | 不能批量抓取他人朋友圈 |
| 自己的朋友圈 | 可做（截图/复制） | 无"一键导出全部" |
| 公众号文章 | 可抓正文 | 付费墙、需登录的抓不到 |
| 微信收藏 | 可逐类转发 | 不能直接读收藏接口 |
| 通讯录 | 不可获取 | — |
| 支付/账单 | 不可获取 | — |

## 四、合规红线（不可逾越，不接受"帮我试试"）

1. **不破解、不逆向**：不解析 `EnMicroMsg.db`、不破解 `MM.sqlite`、不使用第三方"微信导出"工具窃取数据。
2. **不冒充、不代操作**：不能代替用户登录、不能操作他的微信客户端（除非用户在场用浏览器控制功能明确授权）。
3. **不外传第三方内容**：群聊里别人说的话，属第三方信息。默认 `privacy_level: sensitive`，不做公开分享、不用于对外产出。
4. **不做人格诊断**：基于聊天记录分析他人，只能描述"言论特征"，不能推断心理疾病、性取向、政治立场等敏感属性。
5. **不生成可识别个人的档案**：人物档案只用于用户自己回顾，不得导出为对外材料。

## 五、隐私脱敏规则

入库前扫描并替换：

| 类型 | 处理 |
|---|---|
| 身份证号 | `110***********1234` |
| 银行卡 / 卡号 | `**** **** **** 5678` |
| 手机号 | `138****8000` |
| 家庭住址 | 保留到"区"，删除门牌 |
| 密码 / 验证码 | **整条删除**，不保留掩码 |
| 医疗诊断 | 保留但 `privacy_level: restricted` |
| 金额 | 保留但 `privacy_level: sensitive` |

脱敏只作用于 `content_clean`；`content_raw` 保留原样（本地库，仅用户可见）。
若用户要求"导出给他人"，则必须导出脱敏版，且明确告知已脱敏。

## 六、质量边界：何时必须说"不确定"

以下情况**必须**标 `confidence: low` 并在汇报时说明，不许含糊过去：

- 语音转写出现明显错字或语句不通
- 截图文字模糊、被压缩
- 链接只拿到标题、没拿到正文
- 顺序可疑（用户乱序勾选）
- 发送人缺失（系统消息、导出残缺）
- 时间缺失（只剩日期或只有相对时间"昨天"）

**汇报模板**：
> 这批 12 条里，第 3、7 条是语音转写，识别质量一般（已标低置信度），建议你听一下原音核对关键词。

## 七、当用户的要求越界时怎么说

不要生硬拒绝，给替代方案：

| 用户说 | 回应 |
|---|---|
| "能不能一次性把我 3 年的记录都弄进来" | "一次拿不到全部。建议按季度合并转发，先做最近一个季度看效果，再决定要不要补历史。" |
| "帮我把这个人的朋友圈都抓下来" | "抓不到别人的朋友圈。你可以截图你看到的那几条，我按截图整理；或者把他发给你的内容转给我。" |
| "这聊天记录里是不是有人有抑郁症" | "这超出了文本能判断的范围，我不做这类推断。不过我可以帮你梳理这段对话里出现过哪些情绪词、集中在什么话题上。" |
| "把这段对话发到群里" | "这段包含第三方发言，导出前我先把人名和联系方式脱敏。" |

## 八、数据安全

- 所有解析在本地完成，`records.csv` / `records.jsonl` 存在用户自己的目录
- 资料库文档受账号权限保护，但**分享链接等于公开**，敏感内容不要生成分享链接
- 原文件（语音、照片）建议用户自己另行备份，系统不做长期二进制存储
- 用户要求删除时：删资料库节点 + 删本地 `kb/` 目录，两处都要清
